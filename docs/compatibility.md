# Compatibility

The module is additive: it does not modify existing Quickshell configurations.
Its core imports QtQuick, QtQuick.Layouts, Quickshell and Quickshell.Io. There
are no compositor-specific imports in the default controller/window.

| Configuration | Behavior | Verification |
| --- | --- | --- |
| Standard `CodexStatus` | Ordinary Quickshell FloatingWindow | Quickshell 0.3.2 runtime and synthetic fixtures |
| Existing bar | Controller plus optional pill in a host-owned row | QML component tests and runnable example |
| Custom popup host | `CodexService` plus `CodexDashboard` | Runnable embedded example |
| Hyprland | Optional adapter with layer window/focus grab | Import/lint and isolated runtime checks |
| Other compositors / X11 | Uses standard Quickshell toplevel APIs | Intended compatibility; not tested across every compositor |

A compositor or window manager may tile, decorate, reposition, or constrain a
standard window. Configure its window rules if you want a floating placement.
Native Hyprland testing confirmed that tab changes do not force its outer window
to resize; Home content stays compact inside the space assigned by the compositor.
The default minimum size is 300 × 280; an unusually small screen or forced
tiling may constrain the layout. This project cannot guarantee every existing
theme, custom Qt plugin, monitor arrangement, or future Quickshell version.

## Codex source

Tested source: Codex CLI 0.163.0 with its existing app-server daemon. The bridge
uses the local `app-server proxy --sock` transport and experimental metadata
capability. An older CLI without those commands or fields is unsupported.
Future daemon versions may require adaptation. Run
`python3 -m codex_status --check` to check capabilities without installing a
service. It reads metadata and prints a redacted capability summary.

The loaded-thread endpoint is a bounded current snapshot. A nickname may be
generated by Codex. A model is displayed only when the individual thread reports
it; the parent's model is never assigned to a child. Missing activity data,
unsupported metadata, and disconnected sources remain visibly unavailable or
stale. Credits are preserved as bounded decimal strings, including tiny values;
they are not converted to a misleading floating-point estimate.

## Desktop services

The backend needs Linux Unix sockets and peer credentials. Its core does not
require systemd. The optional installer-managed service and preferred detached
action launcher use the systemd user manager. When `systemd-run` is absent,
explicit actions use detached subprocesses; when it is installed but its manager
is unavailable, the action fails safely. See [runtime](runtime.md).

The installer deliberately refuses symlinked roots. For symlink-based dotfiles,
choose real directories or manually import a copy of the module. Separate
instances should use explicit `qs -p` paths and their own IPC target names.
